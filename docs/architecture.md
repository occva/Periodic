# 项目结构与职责

Periodic 按职责和单向依赖组织代码，业务行为和外部接口不依赖文件位置：

```text
App ───────────────→ Views
                       ├──→ Features
                       ├──→ Services
                       └──→ Models
Features ───────────→ Services、Models
Services ───────────→ Stores、Models、系统适配器
Stores ─────────────→ Models、Schema
```

下层不反向依赖具体页面或 App 入口；Models 不依赖 SwiftUI、SwiftData 页面状态或系统服务。

## 目录职责

- `App/`：应用入口、Scene 和 Commands，只负责装配。
- `Features/`：窗口或功能范围内的可观察状态、筛选和展示协调；不保存 SwiftData 实体。
- `Models/`：稳定领域枚举、值类型、DTO、输入类型和纯计算。
- `Services/`：依赖聚合、系统客户端、内置资源加载及开发数据准备。
- `Stores/`：SwiftData 容器、事务入口和 `Schema/` 持久化实体。
- `Support/`：环境值、ViewModifier、日志、配置和小型平台胶水。
- `Views/`：按功能分目录；页面根视图、专用组件、布局和草稿类型就近放置。
- `Resources/`：本地化、Asset Catalog、内置目录和图标资源。
- `Tests/`：单元测试，目录名称与被测职责对应。

## 文件组织约定

- 页面根文件只保留页面状态、主体组合、工具栏和用户意图转发。
- 可复用或独立测量的布局使用单独文件，例如 `IndependentColumnLayout`、`TimelineAxisLayout`。
- 纯展示组件不持有 Store 或 Service，通过明确输入、Binding 和闭包接收依赖。
- 表单草稿与行展示模型放在对应功能目录，不混入领域 DTO 或持久化实体。
- 领域文件按稳定概念拆分：日期、金额、分类、DTO、分析模型分别维护。
- 持久化写入只通过 Store；页面不直接操作 `ModelContext`。
- 新增类型优先放入现有职责目录；只有形成新的稳定业务能力时才增加顶层模块。

## 存储与刷新边界

应用入口为每个数据库创建一个 `DatabaseSession`，再将同一 session 传给订阅、模板、分类、内置模板分类及数据交换 Store。session 在后台 `DispatchSerialQueue` 构造 SwiftData 上下文，关闭自动保存，并将所有 Store 的 `unownedExecutor` 显式绑定到该队列；`DefaultSerialModelExecutor` 保有同一个上下文。只通过 Store 的明确保存/回滚提交，禁止为同一个应用数据库分别创建 Store 的执行器。

Store 的数据库操作保持同步 actor 方法，检查 revision/digest、修改实体和 save 之间没有 suspension point。不同功能的读写由同一执行器串行处理，导入预览失效或旧编辑版本必须明确报冲突。数据模型、迁移版本与正式存储位置不变。

窗口使用 `subscriptionDataVersion` 触发保存后的统一刷新，保存回调不再同时主动 reload。同一数据版本的重叠加载共用任务，版本变化取消旧任务并通过 generation 阻止旧结果更新状态；日期、时区和窗口激活仍可主动刷新。订阅编辑保留打开时的 DTO 和 revision，不随列表刷新改成新建或提升保存基线；详情目标消失时关闭详情。

读取坏订阅时，`loadSubscriptions` 返回有效记录和无效记录数量，窗口以持续可见的非模态提示说明异常数量和恢复方式；重载不反复弹窗，全部记录无法转换时也保留提示及数据库原记录。需要完整集合的 `fetchAll` 显式失败。存在坏记录时不核对系统通知，避免用残缺集合撤销提醒。

订阅和模板的图标选择持有文件写入租约。取消/关闭释放未提交图标，保存保留引用中的图标并清理多余选择；并行草稿或导入的租约保护共享文件。启动扫描超过 24 小时的无引用图标，兼容旧 Apple URL 和其旧缓存目录；回收前记录保留代数，期间新提交的图标延后回收并进入重试队列。

资源目录必须与数据库属于同一存储范围。正式数据库沿用既有图标、付款附件及旧缓存目录；显式指定其他数据库时，资源放在该数据库旁的 `<数据库文件名>.assets` 目录，旧图标缓存也限制在此目录内。内存数据库使用独立临时资源目录，XCTest 宿主默认使用内存数据库；显式指定磁盘测试数据库仍须遵守同一资源隔离规则。禁止用一个数据库的引用集合清理另一数据库的资源。

外置图标统一保存本地引用：Apple 主动选图使用 `apple-icon:<本地键>`，新图片默认按内容哈希命名；本地选择和数据包图片使用 `user-icon:<内容哈希>`。同一网址返回新内容时生成独立文件；已有同键文件内容不匹配时为草稿生成独立键，不覆盖已保存记录或其他草稿的文件。确认保存仅切换当前记录的引用，取消只回收本次未提交资源。既有 Apple 网址哈希键保持可读。`StoredIconReference` 是引用身份的唯一规则入口，保存、读取及引用回收均使用同一规则。旧 Apple HTTPS 字符串仅作为迁移输入，不代表展示时联网加载；新保存不再写入网址。

启动时先验证并将旧缓存图片复制到持久目录，再由共享数据库入口在一个事务中转换订阅及模板的引用。引用格式转换不改业务 revision 或时间字段；旧草稿保存也会规范化为本地引用。任一图片准备失败时不转换数据库引用、不进入后续清理，并在列表加载后保留准备错误；下一次准备可重试。旧缓存读取只承担离线迁移，正常选图和导入只写持久目录。移除该迁移入口须以停止支持未完成迁移的历史数据为前提。

## 行为保持要求

结构调整不改变：

- 类型名称和现有调用接口；
- 数据模型、迁移和存储位置；
- 日期、金额、筛选和统计规则；
- 页面输入输出、交互路径与本地化文案；
- 并发隔离、事务边界和错误语义。

每批结构调整后运行现有单元测试；完成后运行完整测试和 Debug 构建。
