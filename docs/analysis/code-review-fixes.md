## 图标误删事故复核与恢复

用户随后发现正式订阅图标变为问号。核实数据库中的订阅仍保留部分 `apple-icon:` 引用，但对应资源目录缺少相关文件。这不是正常孤儿回收，而是此次 M4 修复触发的正式资源误删。

`lifetimeBackfillRunsOnlyOnceSoLaterCopiesKeepEmptyHistory` 使用临时 SQLite 数据库，且显式指定 `inMemory: false`。此前 AppServices 只根据是否为内存库决定资源根目录；临时磁盘库因此回退到正式图标目录。新增启动清理读取临时库的引用集合，把正式库仍引用的旧图标判为孤儿并删除。两类图标目录修改时间与首次完整测试运行时间吻合。原有付款附件装配也存在相同路径混用，虽然此次未确认附件损失，修复同时纠正该装配问题。

因此，前述测试通过只能证明断言通过，不能证明资源隔离正确；此前关于测试不影响正式数据的判断应以此复核纠正。

修正包括：

- 自定义数据库的图标和付款附件使用该数据库旁独立的资源根目录，以数据库文件名区分同目录内的多个数据库；正式路径保持原样。
- AppleIconCache 的显式资源根目录同时限定旧缓存目录，不再回退到正式旧缓存。
- XCTest 宿主默认使用内存数据库和临时资源目录；显式注入的磁盘库继续按数据库路径隔离。
- 新增 3 项回归：宿主默认内存存储、一个数据库的维护不能删除另一个数据库的图标或付款附件、显式图标根目录对旧缓存的隔离。

最新 `./script/test.sh unit`：209 项测试全部通过，参数化共 219 次运行，0 失败；结果为 `build/TestResults/20261008-172423-66569.xcresult`。测试同时完成 Debug 应用及单元测试 target 构建，未新增或运行 UI 测试。

恢复使用事前的含图标导出包，按现有订阅 UUID 对应资源，并核对包内校验和及内容哈希。缺失文件已按当前 `apple-icon:` 引用补回，使用排他创建避免覆盖已有文件；恢复前后只读数据库的逻辑内容哈希一致。恢复仅补回图片，没有导入备份订阅。

大多数订阅的 revision 与备份一致；少量后续有修改的订阅无法从现有备份证明图标是否也发生过变化，因此只能确认恢复资源来自事前备份。

## 统一图标本地引用及共享回收修正

后续独立审查指出：删除和待清理重试按原始字符串判断引用，而文件删除会把旧 Apple HTTPS 网址规范化为本地键。两条记录以不同格式引用同一文件时会误删。该问题已在独立临时数据库和资源目录中复现；首轮新增回归结果为 `build/TestResults/20261008-180210-77982.xcresult`，两种共享目标及旧队列路径均报 `storedImageMissing`，原有 209 项测试通过。

外置图标现统一保存本地标识，保留 Apple 选图及本地上传的来源前缀，不再保存新网址引用。新增 `StoredIconReference` 提供唯一的身份规则，订阅、模板、导入写入及删除差集、清理队列沿用该规则。旧网址仍可作为迁移输入：先从本机旧缓存准备并验证图片，再在一个数据库事务中更新订阅及模板字段；失败保留原引用和原缓存，显示准备错误并允许重试。该过程不进行网络请求，不修改业务 revision 和时间字段。

新增 4 项回归覆盖订阅/模板共享的两种引用删除方向、旧队列保护、离线迁移及幂等、缺图时数据库不部分转换并保留错误提示、恢复图片后的重试成功。既有模板创建测试增加新保存使用本地引用的断言。
