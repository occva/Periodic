# 变更记录与安全撤销规格

> 版本：1.0｜日期：2026-09-23｜状态：方案设计，尚未实现。
> 依赖：[需求文档](../requirement.md)、[架构说明](../architecture.md)、[扩展规格总则](README.md)。

## 1. 目标与设计决策

变更记录回答“何时、通过什么入口、改变了哪些业务事实”；安全撤销在数据仍满足前置条件时，以一项新的领域操作恢复旧状态。

采用两层结构：

1. **ChangeEvent**：长期保存的轻量审计事件，支持活动页、按记录查看、同步和月度分析。
2. **UndoEnvelope**：设备本地、有限期限的完整反向命令材料，仅用于安全撤销。

这两层不能混为普通 OSLog。OSLog 仍只记录故障上下文，不记录名称、备注、金额明细或字段正文。

## 2. 覆盖范围与非目标

### 2.1 记录的操作

- 订阅、周期、付款、模板、分类及生命周期计划的新增、修改和删除；
- 续费、应用历史到当前设置、批量操作；
- AI 确认后的写入、数据包导入和 iCloud 数据集迁移；
- iCloud 合并、冲突解决及远端删除；
- 数据迁移、自动回填和日期核对产生的持久状态变化；
- 对既有事件执行撤销或恢复。

纯读取、搜索、筛选、页面跳转、弹层打开、导出和通知展示不生成业务变更事件。失败或取消的事务不生成成功事件；技术失败进入受控日志和操作回执。

首次启用只写一条 `historyBoundary` 事件并记录 `historyCoverageStart`。不得根据当前订阅、付款或修改时间反推并伪造启用前的逐项事件；依赖历史覆盖率的页面和 AI 月报必须明确标记此前数据不完整。

### 2.2 非目标

- 不提供任意时间点数据库回放或 Git 式分支。
- 不承诺每项系统迁移、数据集切换和远端冲突都可一键撤销。
- 不把审计记录作为付款凭证或服务商取消证明。
- 不允许修改、重排或伪造既有 ChangeEvent。
- 不无限保存完整删除快照和图片副本。

## 3. ChangeEvent 模型

`ChangeEventRecord`：

| 字段 | 说明 |
| --- | --- |
| id | 事件 UUID |
| datasetID | 所属数据集，避免跨库混用 |
| mutationID | 一次事务的稳定 UUID；多实体事件共享 |
| timestamp | RFC 3339 审计时间戳，不作为业务日期 |
| source | user / ai / csvImport / dataPackageImport / cloudMerge / restore / migration / systemDateReconciliation / undo |
| action | create / update / delete / renew / merge / restore / transition / revert |
| entityKind / entityID | 主要实体类型和稳定 UUID |
| parentEntityID | 可选父订阅 ID |
| changedFieldKeys | 稳定字段键集合 |
| summaryPayload | 版本化、结构化且可本地化的摘要参数 |
| relatedEventID | 撤销、重做或冲突解决关联的原事件 |
| deviceID | 随机安装 ID，不含设备名称或 Apple ID |
| schemaVersion | 事件结构版本 |

数据集同时保存 `historyCoverageStart` 和最近一次显式清理边界，供活动页、导出和月度分析判断覆盖率；边界时间不是用户业务变化事件的替代品。

事件不可依赖已删除实体才能显示。`summaryPayload` 可保存当时的短名称、类型、数量、日期和币种代码，但遵循最小化原则：

- 备注、付款备注和取消说明只记录“已修改”，不复制正文；
- 图片只记录添加、替换或移除及内容哈希前缀，不保存路径；
- API Key、Provider secret、AI 对话、文件路径和通知正文永不进入事件；
- 金额变化可以保存精确的前后值和币种，以支持财务纠错审计，但不写入 OSLog。

同一事务可以产生一个父事件和多个实体明细。活动页默认折叠为一次操作，例如“数据包导入：新增 20，更新 3，跳过 2”，避免生成无法浏览的事件洪流。

## 4. UndoEnvelope 模型

`UndoEnvelopeRecord` 仅保存在发起变更的设备：

| 字段 | 说明 |
| --- | --- |
| id / eventID / mutationID | 与原事件关联 |
| inverseCommandKind | 穷举的反向领域命令 |
| encryptedPayload | 恢复所需的版本化载荷；使用应用本地密钥保护 |
| preconditions | 涉及实体及提交后的 expected revision |
| assetReferences | 撤销期内需保留的内容哈希，不保存任意路径 |
| createdAt / expiresAt | 默认可撤销 30 天 |
| state | available / consumed / expired / invalidated / cleanupPending |

每个设备最多保留最近 200 个 envelope，并同时受 30 天期限限制；先达到者生效。清理 envelope 前核对图片是否仍被正式记录或其他 envelope 引用。

应用本地密钥存于 Keychain。密钥不可用时，审计事件仍可读取，但相关撤销标记为不可用；不能静默用明文重新保存载荷。

## 5. 撤销语义

### 5.1 通用流程

```text
选择可撤销事件
    ↓
解密并解析 UndoEnvelope
    ↓
读取当前实体与 revision
    ↓
生成反向操作预览
    ↓
用户确认影响范围
    ↓
通过原领域 Service 原子提交
    ↓
写入新的 revert ChangeEvent
```

撤销从不删除原事件，也不直接覆盖数据库。它是一项新事务，因此会同步、刷新提醒并出现在活动历史中。

### 5.2 前置条件

- 所有受影响实体 revision 与 envelope 记录的提交后 revision 一致；
- 数据集未切换，记录关系和 UUID 未被其他操作占用；
- 所需图片仍存在或可从 envelope 保留区恢复；
- 当前 schema 仍支持该反向命令；
- 没有正在执行的导入、恢复、同步合并或其他维护锁操作。

任一条件不满足时，不提供强制覆盖。用户可查看差异并手动修正，或通过新的编辑操作恢复部分字段。

### 5.3 各类操作

- **撤销新增**：预览将级联删除的周期、付款和计划；若新增后已有后续修改或关联，revision 检查阻止直接撤销。
- **撤销修改**：恢复原事务改动的字段；不修改原事务未涉及字段。
- **撤销删除**：以原 UUID 恢复实体及关系；冲突、缺图或父记录不存在时拒绝自动恢复。
- **撤销续费**：原子恢复订阅当前日期和状态，并删除该续费产生的周期及付款；后续已有付款或修改时不可直接撤销。
- **撤销导入/批量操作**：整个 mutation 作为一个原子撤销单元，不能只撤回其中一行制造关系不一致；可先进入详情手动处理。
- **撤销 AI 操作**：与相同领域命令完全一致，不因来源是 AI 获得更高权限。
- **撤销同步变更**：允许对最新且无后续冲突的远端 mutation 发起“恢复为先前值”，结果作为新的本地 mutation 同步；不能删除远端历史。
- **数据集迁移**：不生成普通 UndoEnvelope。不可逆迁移依赖操作前生成的 `.periodicdata` 安全副本，并由迁移策略保证可回滚候选库。

## 6. 重做与 Cmd+Z

- Cmd+Z 只针对当前焦点窗口最近一次由该窗口成功提交、且仍满足前置条件的本地用户操作。
- 多窗口下不使用一个隐式全局撤销栈；其他窗口或同步修改后，菜单项立即失效并解释原因。
- Cmd+Shift+Z 只在本次运行会话内重做刚撤销的操作，并继续执行 revision 检查。
- 应用重启后仍可在活动页显式“撤销此操作”，但不恢复键盘撤销栈。
- 导入、批量删除、AI、云合并等高影响操作默认通过活动页预览撤销，不抢占普通编辑窗口的 Cmd+Z。

## 7. 活动页面与详情入口

主侧边栏新增“活动”页面，使用单列时间分组列表和详情面板：

- 按今天、昨天、本周、更早分组；
- 可按来源、操作、实体类型、是否可撤销筛选；
- 默认显示本地化摘要、时间、来源和影响数量；
- 选择后显示字段级变化、关联实体、撤销可用性和失效原因；
- 支持打开相关订阅或导入回执；记录已删除时仍能查看事件；
- 只有可撤销事件显示“撤销此操作”，危险影响使用独立确认 Sheet。

订阅详情增加“活动”局部视图，只显示该订阅及其周期、付款、试用和取消计划事件。这里不复制全局筛选状态。

活动页不是日志控制台，不显示堆栈、CloudKit token、HTTP 响应、文件路径或技术调试文本。

## 8. 事务与写入入口

所有业务写入通过统一 `MutationRecorder` 包裹现有领域事务：

```swift
struct MutationContext: Sendable {
    let mutationID: UUID
    let source: MutationSource
    let originReferences: MutationOriginReferences
    let windowID: UUID?
}

protocol MutationRecorder: Sendable {
    func commit<Request: Sendable, Result: Sendable>(
        context: MutationContext,
        request: Request
    ) async throws -> RecordedMutation<Result>
}
```

`MutationOriginReferences` 是只包含可选本地 UUID 的值类型，可关联 AI proposal / Provider / conversation、导入计划、同步批次或原事件；它不保存提示词、响应、host、文件路径或远端 token。

- 领域 Service 产生 typed change set、结果和可选 inverse command，不由 View 比较对象猜差异。
- 提交前先取得 Keychain 密钥、生成并验证加密载荷，并把撤销期需要的图片复制到受管 retention staging；这些步骤失败时不开始业务事务。
- staging 内容按哈希原子提升到 retention 存储后，业务数据、ChangeEvent、完整 UndoEnvelope（含加密载荷和资源哈希）在同一数据库事务提交。
- 数据库事务失败时仅清理本次新建且不被其他 envelope 引用的 retention 文件；清理失败进入可重试维护任务。此顺序最多留下无引用资源，不会留下引用不存在资源的可用撤销项。
- envelope 清理是可重试维护任务，不阻塞普通读取。
- migration 和日期核对同样提供明确 MutationSource，禁止绕过记录器直接修改正式数据。
- 对只读查询不创建 recorder 上下文。
- `mutationID` 同时作为幂等键；相同 ID 的重试只能返回原回执，不能重复提交业务数据、ChangeEvent 或 UndoEnvelope。

## 9. iCloud 与多设备

- ChangeEvent 随私有 CloudKit 数据集同步，以 event ID 去重，事件本身只追加不修改。
- UndoEnvelope、设备本地密钥和 Cmd+Z 栈不同步。
- 远端业务 mutation 到达时，如果其 ChangeEvent 同批可用则直接关联；旧客户端没有事件时，本机生成 source=cloudMerge 的兼容摘要，但不伪造原设备身份。
- 同步 ChangeEvent 不能替代业务 record revision、tombstone 或 mutation journal。
- 撤销产生的新业务 mutation 和 revert event 通过正常同步传播，其他设备只看到结果与历史，不获得本机 envelope。
- 清除云端活动历史是独立高风险操作，首版不提供；数据集整体删除仍按 iCloud 规格执行。

## 10. 导入、导出与保留

- 完整 `.periodicdata` 默认包含 ChangeEvent，使迁移后仍能理解数据来源；manifest 单独声明事件数量和最早时间。
- UndoEnvelope、加密载荷、设备密钥和 Cmd+Z 栈不导出。
- `.periodicdata` V1 不包含变更历史；变更记录模型落地后需提升格式版本才能纳入。
- 合并导入的外部 ChangeEvent 只作为来源历史读取，不能导入为本机可撤销操作；重复 event ID 校验内容一致，否则报冲突。
- 用户删除订阅不会自动删除其 ChangeEvent，否则删除本身将失去审计意义。
- 设置“清除活动历史”必须展示时间范围和影响；清除后不可恢复、不会删除业务数据，并生成一个不含被清除正文的边界事件。启用 iCloud 时须说明该清理将同步。

## 11. AI 与月度分析

- AI 提案确认后，source=ai，并在 `originReferences` 中记录 proposal、Provider 与对话的本地随机 ID，不记录 prompt、回复或 Provider host。
- AI 可以查询事件的结构化摘要，但默认不能读取备注正文或 UndoEnvelope。
- 月度分析按事件 source、action、entityKind 和结构化数值聚合，不把完整字段差异直接发送 Provider。
- AI 不能调用撤销执行工具；只能查找相关活动并生成“建议撤销”的本地提案，最终由原生活动页确认。
- 清除 AI 对话不删除 ChangeEvent；清除活动历史也不修改对话正文。

## 12. 安全、隐私与错误

- UI 中的业务活动历史是用户数据，不写入 OSLog、崩溃报告或遥测。
- 备注等敏感字段只显示“已修改”；撤销需要的正文仅存在本地加密 envelope。
- 解密失败、载荷损坏或 schema 不兼容时保留审计事件，撤销状态改为不可用并提供原因。
- envelope 过期或消费后安全删除载荷；图片保留区只删除确认无业务引用和 envelope 引用的内容。
- 时间戳用于排序和审计，不依据设备时间决定“谁覆盖谁”；并发仍由 revision 和同步冲突规则处理。
- 活动搜索对短摘要建立本地索引，不把内容交给系统 Spotlight，除非未来单独授权。

## 13. 测试与验收

### 13.1 自动化测试

- 每种领域命令生成正确 source、action、字段键、关联和本地化摘要参数。
- 失败、取消和回滚事务不留下成功事件或 envelope。
- 新增、修改、删除、续费、AI、导入和批量操作的撤销往返。
- revision、关系、数据集、schema 和资源变化使旧 envelope 正确失效。
- 30 天、200 项边界及图片保留区清理。
- 多窗口 Cmd+Z 隔离、会话重做和应用重启后的显式撤销。
- iCloud 去重、离线事件、旧客户端兼容及撤销作为新 mutation 传播。
- 数据包往返保留 ChangeEvent 但不包含 UndoEnvelope。
- 敏感字段、Keychain、路径、对话和备注正文不会进入摘要或日志。

### 13.2 验收标准

- **HISTORY-01**：所有成功业务写入具有来源明确且不可修改的 ChangeEvent。
- **HISTORY-02**：失败、取消和事务回滚不会显示为成功活动。
- **HISTORY-03**：备注正文、密钥、对话、路径和 UndoEnvelope 不进入活动摘要或日志。
- **HISTORY-04**：撤销前展示反向影响，并重新验证全部 revision 和关系。
- **HISTORY-05**：撤销是一项新事务和新事件，不删除或篡改原历史。
- **HISTORY-06**：存在后续修改时禁止强制覆盖，用户只能查看差异或手动修正。
- **HISTORY-07**：撤销续费、删除和批量导入保持订阅、周期、付款及图片关系一致。
- **HISTORY-08**：Cmd+Z 按窗口和会话隔离，不撤销其他窗口或远端新操作。
- **HISTORY-09**：ChangeEvent 可同步和完整备份，UndoEnvelope 与本地密钥始终留在设备。
- **HISTORY-10**：过期清理不删除仍被业务或其他 envelope 引用的图片。
- **HISTORY-11**：AI 月度分析只获得允许的聚合事件事实，不能执行撤销。
- **HISTORY-12**：活动页和记录详情支持键盘、VoiceOver、长文本和大数据分页。

## 14. 分阶段落地

1. 定义 MutationContext、typed change set、ChangeEvent schema 与迁移。
2. 接入订阅、周期、付款和生命周期领域 Service，保证事件与业务事务原子提交。
3. 实现活动页、记录详情和来源筛选。
4. 实现本地加密 UndoEnvelope、revision 预览及单项撤销。
5. 接入续费、删除、导入、批量操作、AI 与窗口级 Cmd+Z。
6. 接入 iCloud、数据包、保留清理和 AI 月度聚合。
7. 完成故障注入、多窗口、隐私、性能和可访问性验收。
