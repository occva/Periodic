# Periodic 扩展功能规格

> 版本：1.1｜日期：2026-09-24｜状态：部分扩展已实现，其余按各规格状态推进。

本目录集中描述需要独立架构边界的扩展与横切能力。iCloud、AI、菜单栏、生命周期计划和变更记录属于独立扩展，其中 iCloud 与 AI 会突破“离线优先、无账号、无通用 HTTP 服务”的现有边界；数据导入导出当前只提供 `.periodicdata` 完整数据包。核心订阅、金额、日期、周期、付款及删除规则仍以 [需求文档](../requirement.md) 和现有实现文档为准；扩展文档只覆盖新增能力及其边界。

## 共同原则

- iCloud 与 AI 默认关闭且分别启用；`.periodicdata` 数据交换、菜单栏速览、生命周期计划和变更记录是本地能力，不因此发起网络请求。
- 扩展不能绕过现有 Service / Use Case 直接写 SwiftData，也不能降低 revision、事务和确认要求。
- 金额继续使用最小货币单位，日期继续使用无时区偏移的 Gregorian 本地日历日。
- 不在日志、诊断、崩溃信息、通知或分析数据中记录 API 密钥、完整备注、对话正文或金额明细。
- 扩展失败不得删除正式本地数据，不得静默切换数据集，也不得以空数据伪装同步或请求失败。
- iCloud 与 AI 分别授权：启用一个扩展不代表同意另一个扩展访问或传输数据。

## 与现有约束的关系

现有 `AGENTS.md` 和架构文档规定不引入云同步及通用 HTTP 服务。iCloud 与 AI 两份规格是产品范围变更提案；进入实现前必须分别更新对应约束、工程 entitlement、隐私说明和测试矩阵。规格获批本身不等于授权直接修改生产权限。数据导入导出继续遵循本地、沙盒和用户显式授权边界；CSV、复制导入和筛选导出不属于当前计划。
