# 数据导入与导出规格

> 版本：1.1｜日期：2026-09-24｜状态：方案设计与当前代码落地计划，尚未实现。
> 依赖：[需求文档](../requirement.md)、[架构说明](../architecture.md)、[扩展规格总则](README.md)。

## 1. 格式决策

Periodic 采用“双轨格式”，不把 CSV 当作完整数据格式：

| 格式 | 定位 | 数据范围 | 主要用途 |
| --- | --- | --- | --- |
| Periodic 数据包 | 主格式 | 订阅、周期、付款、模板、分类、用户图片及可选设置 | 完整迁移、备份、恢复、选择性导入 |
| CSV | 兼容格式 | 当前订阅字段，不含历史、图片和设置 | Excel / Numbers 查看、编辑和批量交换 |

主格式使用 Finder 视为单一文档的 macOS package，扩展名为 `.periodicdata`，UTType 为 `local.lhg.periodic.data-package`。package 本质是目录，但用户通过系统文件面板把它当作一个文件操作，因此：

- 不需要第三方 ZIP 依赖或启动外部进程；
- 可流式写入多份 JSON Lines 和图片，不必一次把全库加载到内存；
- 单个资源可独立校验和恢复，损坏定位明确；
- App Sandbox 可通过 `fileImporter` / `fileExporter` 和安全作用域 URL 正常访问。

如未来需要跨平台传输，可增加内容完全相同的压缩封装；压缩只是容器变化，不产生第三套业务语义。首版导入不接受任意 ZIP，避免路径穿越、解压炸弹和实现分叉。

本规格获批后，原需求中的 CSV 继续作为兼容交换；“完整 ZIP 备份”调整为 Periodic 数据包。业务规则、预览和恢复安全要求保持不变。

## 2. 目标与非目标

### 2.1 目标

- 用户可完整导出并恢复自己的业务数据和用户图片。
- 用户可导出当前筛选、选中项目或全库，并在导入前看到准确影响。
- 支持新建导入、按 UUID 更新、跳过、复制为新记录和整体替换。
- 导入失败不改变正式数据库和图片目录；导出失败不留下被误认为成功的文件。
- 大数据量下采用快照、流式编码和批量验证，不阻塞主窗口。
- 文件格式有明确版本、校验和、兼容策略和安全上限。

### 2.2 非目标

- 不通过名称猜测同一订阅，也不自动跨币种换算。
- 不导入银行账单、邮件、收据图片或第三方密码管理器数据。
- 不把导入当作自动续费，不根据文件日期自动生成付款或周期。
- 首版数据包不加密；涉及敏感备注时必须提示用户妥善保管。
- 不在后台自动扫描 Downloads、iCloud Drive 或其他目录。

## 3. 用户入口与流程

### 3.1 入口

- File 菜单：导入数据、导出数据、完整备份、恢复备份。
- Overview 工具栏：导入；导出当前结果或选中项目。
- Settings“数据”页面：完整备份、整体恢复、清除数据和最近操作记录。
- 空库页面：从 Periodic 数据包恢复、从 CSV 导入。

所有入口调用同一 `DataExchangeService`，不能在页面中各自实现解析和写入规则。

### 3.2 导出流程

```text
选择格式与范围
    ↓
显示数据摘要和不包含内容
    ↓
选择系统保存位置
    ↓
取得一致只读快照
    ↓
写入同目录临时 package
    ↓
生成校验和并自校验
    ↓
原子移动为最终文件
    ↓
显示数量、大小和位置
```

用户取消保存面板或导出进度时，删除本次临时内容，不改变数据库。最终目标已存在时使用系统覆盖确认，不自行覆盖。

### 3.3 导入流程

```text
系统文件选择器
    ↓
安全作用域内只读打开
    ↓
识别格式、版本、大小和校验和
    ↓
解析到隔离的 ImportWorkspace
    ↓
逐项校验、建立引用图和冲突清单
    ↓
用户选择处理方式并查看最终预览
    ↓
生成绑定文件摘要及数据集 revision 的 ImportPlan
    ↓
再次确认
    ↓
维护锁内原子提交数据库与图片
    ↓
刷新数据、提醒和统计，展示回执
```

读取或预览不会修改正式数据。关闭窗口后丢弃尚未确认的 workspace 和 plan。

## 4. Periodic 数据包结构

```text
My Subscriptions.periodicdata/
├── manifest.json
├── data/
│   ├── subscriptions.jsonl
│   ├── periods.jsonl
│   ├── templates.jsonl
│   ├── categories.jsonl
│   ├── builtin-category-assignments.jsonl
│   └── settings.json
├── assets/
│   └── <sha256>.<png|jpg>
└── checksums.json
```

仅导出部分数据时仍保留相同目录结构，不适用文件可以不存在，但必须在 manifest 中声明。

上述是首个可发布的 `formatVersion = 1`，只包含当前已有的订阅、周期历史、用户模板、分类、内置模板分类覆盖和图标。付款、试用/取消计划及变更记录尚无持久化模型，不能在 V1 manifest 中伪造空表表示“已备份”。这些模型落地后增加对应文件，并提升 `formatVersion` 和 `minimumReaderVersion`；旧版应用必须拒绝会丢弃新实体的整体恢复。

### 4.1 manifest

```json
{
  "format": "periodic-data-package",
  "formatVersion": 1,
  "minimumReaderVersion": 1,
  "exportID": "UUID",
  "sourceDatasetID": "UUID",
  "createdAt": "2026-09-23T10:30:00Z",
  "appVersion": "1.0.0",
  "calendar": "gregorian",
  "scope": "full",
  "tables": {
    "subscriptions": 125,
    "periods": 248,
    "templates": 8,
    "categories": 3,
    "builtinCategoryAssignments": 6
  },
  "assetCount": 12,
  "includesSettings": true
}
```

- 时间戳使用 RFC 3339 UTC，仅用于审计；业务日期使用 `YYYY-MM-DD`。
- `sourceDatasetID` 用于识别同源数据和生成默认冲突策略，不限制导入到其他数据集。
- 未知的可选 manifest 字段忽略；未知必需能力通过 `minimumReaderVersion` 拒绝。
- 路径均为规范相对路径，manifest 不保存设备用户名、绝对路径或 Apple ID。

### 4.2 JSON Lines 记录

每行一个 UTF-8 JSON 对象。优点是可流式处理、可定位具体错误行，并允许大文件不一次性解码。

共同字段：

| 字段 | 说明 |
| --- | --- |
| id | 稳定 UUID |
| recordVersion | 该记录结构版本 |
| revision | 导出时业务 revision；导入时不直接覆盖本地 revision |
| createdAt / updatedAt | 原始审计时间 |

金额保存为 `minorUnits`、`currencyCode`、`currencyScale`，禁止使用浮点数。业务日期保存为 Gregorian `YYYY-MM-DD`，禁止时间戳替代。枚举保存稳定 raw value；无法识别的必需值产生逐行错误。

关系使用 UUID，例如 period 的 `subscriptionID`、payment 的 `subscriptionID` 和可选 `periodID`。顺序不表达关系。

### 4.3 图片

- 文件名以 SHA-256 内容哈希为主键，只允许 `.png` 和 `.jpg`。
- icon metadata 保存 MIME、字节数、像素尺寸和哈希。
- 导出前重新计算哈希；数据库声明与文件不一致时终止，不输出损坏包。
- 导入时验证真实格式、可解码性、大小、像素上限和哈希，再写入临时受管目录。
- 内置模板图标不写入 package，只保存稳定资源名；目标应用缺少该资源时显示明确警告和占位图标。

### 4.4 校验和

`checksums.json` 为除自身外的每个文件记录 SHA-256，包括 `manifest.json`。读取顺序为：路径安全检查、大小上限、读取 checksums、校验 manifest、解析 manifest、校验其余文件、业务解析。校验和用于发现损坏，不是数字签名，不能证明文件来源可信。

## 5. 导出范围

| 范围 | 包含内容 |
| --- | --- |
| 完整备份 | 全部业务记录、用户模板、分类、用户图片和可选业务设置 |
| 全部订阅 | 全部订阅及其周期、付款、生命周期计划、关联变更事件和引用图片；不含无关模板 |
| 当前结果 | 当前筛选命中的订阅及其完整历史、计划、关联事件和引用图片 |
| 选中项目 | 明确选中的订阅及其完整历史、计划、关联事件和引用图片 |
| 模板库 | 用户模板、分类、分类覆盖及引用图片 |

部分导出始终保持引用闭包：导出付款时必须包含父订阅；导出订阅时包含其周期和付款。不能为了缩小文件留下孤儿记录。

设备本地状态、窗口偏好、系统通知授权、待发送通知、iCloud token、同步 journal、UndoEnvelope、本地撤销密钥、AI Provider、API Key、AI 对话和 AI 月度报告均不进入数据包。

## 6. 导入模式与冲突

### 6.1 模式

1. **合并**：保留现有数据，按 UUID 生成新增、更新、跳过和冲突。
2. **复制导入**：为选择的根记录生成新 UUID，并重写其内部关系；适合重复使用样例或跨数据集合并。
3. **整体恢复**：验证完整备份后替换活动数据集；默认先提供导出当前数据入口。

CSV 只支持合并和新建，不支持整体恢复。

### 6.2 UUID 合并

- UUID 不存在：默认新增。
- UUID 存在且内容相同：跳过。
- UUID 存在且内容不同：展示字段差异，由用户选择保留本地、使用导入值或逐字段处理。
- 名称相同但 UUID 不同：视为两条记录，仅提示可能重复，不自动合并。
- 导入 revision 仅用于判断同源历史，不把较大数字当作“更新”；提交后由本地 Store 生成新 revision。

付款和周期是历史事实。其 UUID 冲突必须逐条处理，不能用当前订阅的日期、价格或币种重建。模板删除或改名不影响已存在订阅。

### 6.3 字段组

以下字段必须作为一致性组处理，不能从两侧随意拼接出非法状态：

- `billingKind + cycleMonths + expiry + reminderEnabled`
- `amountMinor + currencyCode + currencyScale`
- `period.start + period.end + period.billingKind`
- `payment.amount + payment.currency + paymentDate`
- `trial.start + trial.end + trial.state`
- `cancellation.state + deadlineDay + effectiveEndDay`
- `iconAssetID + icon content hash`

用户逐字段合并后仍必须通过完整领域校验。

### 6.4 删除语义

普通合并文件不表达“文件里没有即删除”。只有 manifest 明确包含经过用户确认的 tombstone 时才生成删除提案，且仍展示级联影响。完整恢复按整体替换规则处理，不把缺失记录逐条解释为删除操作。

## 7. CSV 兼容格式

CSV 保留用于表格软件，标准列为：

```text
schemaVersion,id,name,symbolName,category,managementState,billingKind,periodStart,expiryDate,cycleMonths,periodAmount,currency,note,reminderEnabled,renewalIntent
```

### 7.1 导出

- UTF-8，首行固定表头，RFC 4180 引号规则，行尾统一。
- 用户文本继续使用公式前缀保护，并在导出预览中说明。
- 日期为 `YYYY-MM-DD`，金额为按币种精度格式化的十进制字符串。
- 不导出周期、付款、图片、设置、revision 或派生状态。
- 启用生命周期扩展后的原生 CSV 使用 schemaVersion=2，并输出 `renewalIntent` 当前字段；旧格式或外部 CSV 缺失时，新建默认为 undecided、更新保留原值。
- 不导出试用与取消计划或变更事件；CSV v2 的 `renewalIntent` 也不包含计划状态。
- 筛选导出必须明确标注数量，不能让用户误以为是完整备份。

### 7.2 导入

- 支持标准表头自动识别和外部列手动映射。
- 外部枚举值、日期格式、币种及布尔文本先形成映射预览。
- 缺失 ID 时生成 UUID；相同 UUID 默认进入更新预览。
- CSV 不生成付款和周期历史，也不清理文件未包含的现有字段。
- CSV 不创建或修改试用、取消计划，也不导入外部 ChangeEvent 行；确认导入本身仍生成一条本地 csvImport 变更事件。导入 `renewalIntent=cancelAtPeriodEnd` 也不据此猜测取消计划。
- 坏行必须修正或由用户明确排除，不能静默跳过。

详细金额、日期、旧格式和公式转义规则继续沿用需求文档 CSV-01～10；本规格只调整 CSV 的产品定位。

## 8. 原子提交与图片补偿

### 8.1 合并导入

1. 在受管图片目录内的随机 staging 子目录准备并验证所有新图片。
2. 获取唯一数据库写入口和当前 dataset revision。
3. 重新验证 ImportPlan、记录 revision 和目标分类等引用。
4. 将新图片按内容哈希原子提升到受管存储；已有相同哈希时复用现有文件。此时图片尚未被数据库引用。
5. 在单一数据库事务中提交全部新增、更新及关系变化。
6. 数据库事务失败时，仅删除本次新建且仍无引用的图片；清理失败记录为可重试维护任务，数据库仍保持提交前状态。
7. 清理被替换且不再被引用的旧图片须晚于数据库事务成功；清理失败不回滚已成功的业务写入，但必须报告并可重试。

提交顺序固定为“先确保目标图片存在，再提交数据库引用”。任何进程中断最多留下无引用图片，不能留下指向不存在文件的正式记录；启动维护任务可安全回收确认无引用的 staging 和内容哈希文件。

### 8.2 整体恢复

恢复在独立 staging 数据库中完成全部解析和校验。确认后关闭现有容器，通过可恢复文件交换切换数据库和图片目录；启动新容器并核对数量、引用和校验和后才删除旧副本。任何一步失败都恢复原活动数据集。

导入期间使用维护锁。其他窗口可继续查看提交前快照，但编辑、AI 写提案执行、同步合并和清空操作必须暂停并说明原因。

## 9. ImportPlan 与接口

```swift
struct ImportPlan: Sendable {
    let id: UUID
    let sourceDigest: SHA256Digest
    let sourceFormat: ImportFormat
    let targetDatasetID: UUID
    let targetDatasetRevision: Int64
    let operations: [ImportOperation]
    let assetOperations: [AssetImportOperation]
    let warnings: [ImportWarning]
    let expiresAt: Date
}

protocol DataExchangeService: Sendable {
    func previewExport(_ request: ExportRequest) async throws -> ExportPreview
    func export(_ request: ConfirmedExportRequest) async throws -> ExportReceipt
    func inspect(_ source: ImportSource) async throws -> ImportInspection
    func plan(_ request: ImportPlanningRequest) async throws -> ImportPlan
    func execute(_ plan: ImportPlan) async throws -> ImportReceipt
}
```

- `ImportSource` 只暴露已授权 URL 的窄读取能力，不把安全作用域 URL 长期保存在业务模型。
- Parser、validator、planner 和 executor 分离；预览阶段不得获得写入 Store。
- `ImportPlan` 绑定源文件摘要和目标数据集 revision。文件或数据库变化后必须重新预览。
- `ImportReceipt` 记录新增、更新、跳过、复制、删除、排除、警告和失败数量，但不包含完整用户文本。

## 10. 安全与资源限制

- 拒绝符号链接、硬链接、绝对路径、`..`、隐藏可执行文件和 manifest 未声明文件。
- package 总大小、单文件大小、记录数、行长度、JSON 嵌套深度和图片像素数均有上限。
- 解析采用严格 Codable schema；不执行文件中的脚本、公式、URL 或命令。
- 导入时不会根据 icon URL 联网下载；缺少图片只产生错误或用户确认的占位。
- 文件读取只在安全作用域生命周期内完成，结束后立即释放权限。
- 临时 workspace 使用随机专用目录，成功或失败后清理；崩溃遗留在下次启动安全清理。
- 导出文件未加密，确认页明确提示其中可能包含名称、金额、日期和备注。

## 11. 进度、取消和错误

导入导出阶段必须可观察：`preparing / reading / validating / planning / awaitingConfirmation / writing / verifying / completed / failed / cancelled`。

- 读取、解析和写临时文件阶段可取消。
- 进入最终数据库事务或文件交换后暂时禁用取消，完成后报告结果。
- 进度使用已处理字节和记录数，不伪造平滑百分比。
- 错误包含文件、表、行号、字段和恢复动作；日志不记录该行正文。
- 多个文件导入不自动串联为一个事务。首版一次只处理一个数据包或一个 CSV。

## 12. iCloud 与 AI 联动

- iCloud 数据集导入完成后，变化作为普通本地 mutation 进入同步队列；不能直接写 CKRecord 绕过同步合并器。
- 整体恢复到启用 iCloud 的数据集前必须说明将同步到其他设备，并要求额外确认。
- 同步正在应用远端批次时，导入计划等待维护锁；不得让两个写入并发覆盖。
- AI 可以解释导入结果或帮助生成列映射建议，但不能读取原始文件正文，除非用户明确把该文件交给 AI Provider。
- AI 不得替用户确认导入、覆盖、删除或整体恢复。
- Provider、API Key、对话和月度报告默认不导出；数据包导入也不能修改 AI 设置。

## 13. 可访问性与交互

- 文件面板使用系统组件；拖放文件与菜单入口调用同一检查流程。
- 预览表可按新增、更新、冲突、错误和排除筛选，键盘可到达每个处理选项。
- 差异显示使用字段名和“本地/导入”文本，不只使用红绿颜色。
- VoiceOver 播报当前阶段、进度摘要、错误行数和确认按钮的实际影响。
- 大预览使用虚拟列表；不会一次创建所有行视图。

## 14. 测试与验收

### 14.1 自动化测试

- 数据包全量、筛选和选中导出的引用闭包及稳定排序。
- 金额精度、Gregorian 日期、Unicode、空备注、零金额和终生记录往返。
- 周期、付款、订阅、模板、分类和图片关系完整性。
- 试用、取消计划及 ChangeEvent 的关系完整性；UndoEnvelope 和 AI 月报不进入数据包。
- 未知可选字段、未来必需版本和不兼容 recordVersion。
- 校验和错误、图片损坏、路径穿越、符号链接、超大文件和超深 JSON。
- UUID 新增、相同跳过、冲突、复制导入和整体恢复。
- 文件变化、数据集 revision 变化及多窗口修改使 ImportPlan 失效。
- 数据库失败、图片移动失败、进程中断和恢复补偿。
- CSV 引号、换行、公式前缀、映射、坏日期、币种歧义和重复 ID。
- 1,000 条订阅、10,000 条付款和大量图片下的内存及耗时基准。

测试生成的数据包放在临时目录，不能读写正式用户库。格式兼容测试保留每个已发布 formatVersion 的只读 fixture。

### 14.2 验收标准

- **EXCHANGE-01**：默认完整导出使用 `.periodicdata`，包含全部业务历史和用户图片。
- **EXCHANGE-02**：CSV 明确标记为当前订阅交换，不被描述为完整备份。
- **EXCHANGE-03**：导出读取一致快照，失败或取消不留下可误用的最终文件。
- **EXCHANGE-04**：导入预览前不修改数据库或图片目录。
- **EXCHANGE-05**：每个冲突都有明确处理结果；名称相同不自动合并。
- **EXCHANGE-06**：金额、币种、日期、终生和历史规则往返后保持不变。
- **EXCHANGE-07**：合并事务失败不写入部分记录；图片失败有补偿且不产生半引用。
- **EXCHANGE-08**：整体恢复失败后原数据库和图片仍能正常打开。
- **EXCHANGE-09**：损坏校验和、越界路径、符号链接和资源超限在写入前被拒绝。
- **EXCHANGE-10**：ImportPlan 绑定文件摘要及数据集 revision，过期计划不能执行。
- **EXCHANGE-11**：导入成功后统计、时间线、详情、提醒及其他窗口统一刷新。
- **EXCHANGE-12**：iCloud 开启时导入变更通过正常同步 journal 传播。
- **EXCHANGE-13**：AI Provider、密钥、iCloud token 和设备状态不会进入导出包。
- **EXCHANGE-14**：用户可使用键盘和 VoiceOver完成选择、冲突处理和确认。

## 15. 当前代码基线与缺口

截至 2026-09-24，仓库中没有可用的订阅导入或导出功能。界面中的“CSV 导入”仅是空闭包或 disabled 占位，`AppCommands` 和 Settings 也没有数据交换入口。

| 能力 | 当前代码事实 | 落地前必须补齐 |
| --- | --- | --- |
| 持久化实体 | 已有 `SubscriptionRecord`、`SubscriptionPeriodRecord`、`ServiceTemplateRecord`、`TemplateCategoryRecord` 和内置模板分类覆盖 | V1 数据包仅对这些实体作出完整性承诺 |
| 付款、计划、变更记录 | 尚无 Schema 和 Store | 不写入 V1；对应功能落地后随数据包版本升级 |
| 一致快照 | Store 分散且没有全库 revision | 增加 dataset metadata 和共享写入协调器，所有写操作递增 revision |
| 原子批量导入 | `SubscriptionStore.create([Input])` 只支持新建订阅，不处理模板、分类、冲突和图标 | 新增专用 `DataExchangeStore`，一次 `save()` 提交整个 plan，失败 rollback |
| 图标 | `AppleIconCache` 以 `apple-icon:` / `user-icon:` 引用本地字节，内置图标使用资源名 | 对所有被引用的非内置图标导出字节、真实类型和 SHA-256，导入后重写本地引用 |
| 文件权限 | Entitlements 只有 `com.apple.security.files.user-selected.read-only` | 导出前改为 `com.apple.security.files.user-selected.read-write`；仍只访问用户在系统面板中选择的路径 |
| 功能装配 | `AppServices` 未提供数据交换服务，页面直接持有 Store 闭包 | 在 App 入口统一装配 service/store/file adapter，View 只发送意图 |

特别注意：不能把使用中的 `default.store` 或 SQLite/WAL 直接复制为备份。这既无法保证快照一致，也会把 SwiftData 内部结构变成永久公开格式。

`DataPackageReader/Writer` 只处理文件协议，不依赖 SwiftData；`DataExchangeStore` 只接收已验证的领域记录和 plan，不解析文件；`DataExchangeFeature` 不直接发起数据库事务。

### 16.2 写入协调与快照

1. 新增唯一 `DatasetMetadataRecord`，保存 `datasetID`、`storeRevision` 和 `schemaVersion`。
2. `SubscriptionStore`、`TemplateStore`、`TemplateCategoryStore` 及内置分类写入都先从 `DatabaseWriteCoordinator` 取普通写入租约，并在与业务记录相同的 `ModelContext.save()` 中递增 `storeRevision`。
3. 导出获取短暂的 snapshot 租约；`DataExchangeStore` 在一个 actor 中不跨 `await` 地 fetch 全部相关记录，转成 `Sendable` 快照后立即释放租约。文件编码使用快照，不长时间锁库。
4. 导入预览记录 `datasetID + storeRevision + sourceDigest`。确认时取独占维护租约，三者任一变化即返回 `stalePlan`。
5. `DataExchangeStore.execute` 在一个 `ModelContext` 内完成新增、更新、关系重写和 revision 递增，只调用一次 `save()`；任何错误立即 `rollback()`。
6. 提交成功后由 `AppServices` 一次性发布订阅和模板数据版本变化，所有窗口使用现有 version 机制刷新。

普通 Store 不得持有维护租约后等待 UI 或网络；导入也只在最终原子提交阶段取独占租约。

### 16.3 V1 数据包映射

| 文件 | 来源 | 顺序 | 导入要点 |
| --- | --- | --- | --- |
| `subscriptions.jsonl` | `SubscriptionRecord` | UUID 字符串升序 | 复用 `BillingKind`、`Money`、`LocalDate` 规则；不自动生成历史 |
| `periods.jsonl` | `SubscriptionPeriodRecord` | subscriptionID、startDay、UUID | 父订阅必须存在；终生周期结束日使用现有领域边界 |
| `templates.jsonl` | `ServiceTemplateRecord` | UUID 升序 | `customCategoryID` 必须指向包内或本地已有分类 |
| `categories.jsonl` | `TemplateCategoryRecord` | UUID 升序 | 同名不代表同一对象，UUID 冲突进入预览 |
| `builtin-category-assignments.jsonl` | `BuiltinTemplateCategoryAssignmentRecord` | templateKey 升序 | 目标版本不认识 templateKey 时警告并跳过，不阻断其他数据 |
| `settings.json` | 明确白名单 | key 升序 | 首版只包含外观、语言、常用/默认币种和菜单栏偏好；导入前可单独取消勾选 |

`iconResourceName` 只保存稳定内置资源名。`iconURLString` 如为 `apple-icon:` 或 `user-icon:`，writer 必须通过窄的图标存储接口读出字节，按内容哈希去重写入 `assets/`；包内记录引用 asset ID，不携带原设备缓存键。

### 16.4 文件和系统面板

- 在工程中导出 `local.lhg.periodic.data-package` UTType，声明 package 扩展名 `.periodicdata`。
- 由于要流式写目录 package 并在目标同级完成原子替换，使用一个窄 `NSSavePanel` / `NSOpenPanel` 适配比把整个 package 构造成内存 `FileWrapper` 更合适。
- panel 只返回一次性 `AuthorizedFile`；适配器在操作期间成对调用 `startAccessingSecurityScopedResource` / `stopAccessingSecurityScopedResource`，不保存书签或绝对路径。
- writer 先在目标同级随机名称中写入，close 所有文件、生成校验和并自校验后，再使用 `FileManager.replaceItemAt` 或等价原子 rename 发布。
- 当前 read-only entitlement 必须调整为 user-selected read-write；不增加 Downloads、Documents 或全盘权限。

### 16.5 UI 状态与入口

- `DataExchangeFeature` 由 `ContentView` 按窗口持有，导入向导和导出 sheet 不跨窗口共享草稿。
- File 菜单通过 `FocusedValue` 调用当前窗口的导入/导出意图；Dashboard、Overview、Timeline 的占位按钮调用同一入口。
- Overview 导出范围由当前窗口显式传入 `all / currentResult(ids) / selected(ids)`，必须在确认页显示数量；其他页默认全库，不偷读 Overview 状态。
- Settings 增加“数据” Tab，放置完整备份、整体恢复和 CSV 兼容交换；清空数据仍使用独立高风险确认流程。
- 页面只渲染 `DataExchangeFeature.State`；解析和文件 I/O 在非 MainActor 服务中执行，搜索/重新映射使用可取消任务及 generation 校验。

### 16.6 CSV 垂直切片

CSV 是兼容交换，但可在数据包导出基础就绪后作为第二个可验收切片：

1. 先实现标准列的全库/当前结果/选中项导出，并使用与数据包相同的 snapshot API。
2. `CSVEncoder` 固定 UTF-8 BOM + CRLF，对用户文本先做公式前缀保护，再做 RFC 4180 引号转义。
3. `CSVParser` 使用逐字节/字符状态机，保留记录号和起始物理行号；不允许 `components(separatedBy: ",")` 或逐行分割。
4. 标准表头先支持自动映射；外部文件的列映射和枚举值映射作为后续子阶段，但从第一版就保留 inspection / mapping / plan 边界。
5. 导入只产生当前订阅的 create/update，不生成 `SubscriptionPeriodRecord`。这需要专用导入写入路径，不能直接循环调用会自动生成 initial period 的 `SubscriptionStore.create`。
6. 预览中坏行默认阻止提交；用户可修正映射或明确排除，不提供“忽略所有错误”快捷操作。

### 16.7 建议实现顺序

1. **基础边界**：增加 UTType、read-write 用户选择文件权限、`AuthorizedFile`、格式值类型和文件面板适配器。
2. **一致性前置**：增加 `DatasetMetadataRecord` 和 `DatabaseWriteCoordinator`，把现有所有 Store 写入纳入 revision/租约，先用多窗口测试验证。
3. **V1 完整导出**：实现全库 snapshot、数据包 writer、图标去重、校验和和自校验，打通 File 菜单及 Settings 入口。
4. **只读 inspector**：实现资源限额、路径安全、校验和、版本兼容及引用闭包检查；此阶段仍不写库。
5. **整体恢复**：在 staging 容器和图标目录中重建数据，通过可恢复指针/目录切换激活，不在正式库内逐条覆盖。
6. **合并和复制导入**：实现 UUID 冲突计划、差异 UI、关系重写、图标补偿和原子提交。
7. **CSV 交换**：先导出和标准模板回导，再增加外部列/值映射；所有写入复用同一 ImportPlan 和维护锁。
8. **安全与规模验收**：格式 fixture、模糊测试、故障注入、1,000 订阅压测、键盘/VoiceOver 和中英文案。

完整数据包优先于 CSV 实现；不能先让 CSV 承担历史和图片，再在后续版本中修补不可逆的信息丢失。
